# Hejhome 3.0 베타 사용 안내

대상 버전: **3.0.0-beta.1**. 현재는 로컬 출시 후보이며 아직 npm에 게시하지 않았습니다.

## 설치 전에

이 베타는 Hejhome 플러그인의 시험 버전입니다. Homebridge 자체를 베타로 바꿀 필요는 없습니다. Homebridge 정식 2.4 이상, UI 5.29 이상, Node 22.13.0 이상·24·26을 사용합니다. Homebridge 1 사용자는 기존 플러그인 2.0 버전을 유지해 주세요.

게시된 뒤 Homebridge 플러그인 메뉴에서 다른 버전을 선택하거나, 실행 중인 Homebridge와 같은 설치 환경에서 다음처럼 명시적으로 베타를 선택합니다.

```sh
# 3.0.0-beta.1 게시 후 해당 버전 설치
npm install -g @chazepps/homebridge-hejhome@3.0.0-beta.1

# 게시된 베타 채널 선택
npm install -g @chazepps/homebridge-hejhome@beta
```

`3.0.0-beta.1` 게시 전에는 `@beta`가 이전 베타를 가리킬 수 있습니다. 설치할 버전 번호를 확인해 주세요. 일반 설치와 업데이트는 `latest`를 사용합니다. 베타 게시가 기존 정식 버전의 `latest`를 바꾸지 않도록 별도 검증합니다. 이 준비 작업에서는 게시·태그 push·운영 설치를 하지 않았습니다.

## 연결과 장치별 설정

- **다른 스마트홈 앱에 연결(Matter)**: Google Home·SmartThings 등에서 사용할 장치를 준비합니다. Homebridge의 해당 브리지에서도 Matter를 켠 뒤 표시된 QR로 연결합니다. 같은 장치를 Apple Home과 Matter 양쪽으로 같은 앱에 추가하면 두 개로 보일 수 있습니다.
- **적응형 조명**: 지원하는 색온도 조명에서 시간대에 따라 색을 조절합니다. 설정 화면과 Apple Home 양쪽에서 켜야 합니다. RGBW라는 이름만으로 색온도 조절을 지원한다고 가정하지 않습니다.
- **장치별 설정**: Apple Home, Matter, 둘 다, 표시하지 않음 중 선택하고 표시 이름을 바꿀 수 있습니다. 지원하는 스위치·릴레이·플러그는 Home 앱에서 보이는 형태도 선택할 수 있습니다. 바뀐 내용은 저장 후 Homebridge를 다시 시작하면 적용됩니다.
- Matter에서는 앱의 이름 길이 제한에 맞춰 긴 이름이 짧게 보일 수 있습니다. 원래 장치 이름과 식별자는 유지하며 여러 채널의 번호도 구분합니다.
- 연결 방식과 표시 형태를 바꾸면 앱의 장치가 없어졌다 다시 나타나거나 별도 연결이 필요할 수 있습니다. 저장 화면에서 변경 안내를 확인해 주세요.

Matter를 사용해도 헤이홈 클라우드는 계속 필요합니다. 기기가 직접 로컬 통신이나 Thread를 지원하게 되는 것은 아닙니다. Homebridge의 Matter는 커뮤니티 구현이며 인증된 상용 Matter 제품은 아닙니다.

## 연결 상태 살펴보기

장치를 찾았는지, Homebridge에서 Apple Home/Matter용으로 준비했는지, 최근 상태를 받았는지, 마지막 명령을 보냈는지 각각 보여줍니다. 이전에 저장된 장치나 연결 준비가 실제 앱 페어링 완료를 뜻하지는 않습니다.

`명령 전송 완료`는 헤이홈 서버가 요청에 응답했다는 뜻입니다. 장치가 실제로 동작했는지 확인하려면 뒤이어 받은 상태나 실물을 확인해야 합니다. 최근 상태를 확인할 수 없을 때는 정상값을 만들어 보여주지 않습니다.

로그인 정보가 만료되면 다시 로그인해 주세요. 새 로그인 정보가 저장되면 연결을 다시 준비합니다. 재연결 뒤에는 장치 목록을 다시 확인하며, 일부 조회가 실패했다고 기존 장치를 바로 지우지 않습니다.

진단 내용 보기에는 계정·비밀번호·토큰·장치 이름·식별자를 포함하지 않습니다. 화면에서 확인한 내용은 개발자에게 자동으로 보내지 않습니다. 로그인 정보, 최근 장치 상태와 문제 확인용 기록은 해당 Homebridge에 저장됩니다.

## 리모컨과 에어컨

확인된 기기 종류에만 버튼이 나타납니다.

- TV·셋톱박스: 소리 크게/작게, 다음/이전 채널, 채널 번호 이동, 소리 끄기/켜기.
- 선풍기: 바람 세기 버튼과 회전 버튼. 실제 단계나 회전 상태를 받지 못하는 기기는 선택한 단계로 바뀌었다고 표시하지 않습니다.
- 에어컨: 설정 온도 16~30°C, 냉방·난방·자동·송풍·제습, 자동·낮음·중간·높음 바람 세기를 선택합니다. 기기가 알려준 현재 설정도 함께 표시합니다. 실제 냉난방이 동작 중이라는 뜻은 아니며 모델에서 지원하지 않는 선택이 있을 수 있습니다.
- 에어컨의 실제 현재 온도를 함께 보려면 별도 헤이홈 온도계를 선택합니다. 확인된 최신 실측값만 표시하며 설정 온도를 현재 온도로 대신하지 않습니다.

전원 상태를 알려주지 않는 IR 장비는 Apple Home에서 순간 전원 버튼으로 보입니다. 실제 켜짐/꺼짐 상태를 확정해서 보여주지 않습니다. 에어컨의 실제 운전 상태를 확인할 수 없어 Apple Home/Matter 온도조절기 위젯은 현재 제공하지 않습니다. 확인된 명령은 설정 화면에서 사용할 수 있습니다.

TV·셋톱박스·선풍기는 장치별 **리모컨 버튼을 Apple Home에 표시**를 켜면 Apple Home에서도 조작할 수 있습니다. 기본값은 꺼짐입니다. 저장하고 Homebridge를 다시 시작하면 기존 기기에 TV·셋톱박스는 음량·채널·음소거 버튼 6개, 선풍기는 바람 세기·회전 버튼 2개가 추가됩니다. 채널 번호 입력은 설정 화면에만 있습니다.

리모컨 버튼은 누를 때 명령을 한 번 보내고 다시 꺼집니다. 켜짐·꺼짐으로 실제 음소거 여부나 회전 상태를 표시하지 않습니다. 옵션을 끄면 추가 버튼만 제거하고 기존 전원 항목과 장치 식별자는 유지합니다. Matter에만 표시하거나 숨긴 장치에는 이 Apple Home 버튼을 추가할 수 없습니다.

설정 화면의 명령도 실행 중인 플러그인의 장치별 대기열을 통해 보냅니다. 응답이 늦다고 같은 명령을 자동으로 다시 보내지 않습니다. 응답을 확인하지 못했다면 실물 동작을 확인한 뒤 다시 조작해 주세요. 설정 화면에서 보내는 리모컨·에어컨·공기청정기 명령은 현재 macOS/Linux에서 제공하며 Windows에서는 사용할 수 없습니다. 기존 Apple Home/Matter 연결과는 별개입니다.

## 밝기 조절과 자동 조명

Matter의 상대 밝기 조절과 길게 누르는 연속 조절을 처리합니다. 연속 조절은 기기 자체의 부드러운 전환 기능을 사용하는 것이 아니라, 제한된 횟수의 밝기 명령을 순서대로 보냅니다. 장치마다 최소 1초 간격, 20초 동안 최대 20회로 제한합니다. 전원·색상 변경, 다른 밝기 조작과 종료 시 멈춥니다.

RGBW에서 흰색과 컬러를 바꿀 때 밝기를 유지합니다. 헤이홈 장면이 실행 중일 때 수동 색상·밝기를 선택하면 컬러 모드로 전환합니다. 이는 장면 프리셋을 새로 제공하는 기능은 아닙니다. 색상을 유지하는 데 필요한 값이 없으면 임의의 색을 만들어 보내지 않습니다. 조명 제조사 응답을 기다리는 동안 상태가 바뀌었을 때도 나중에 도착한 명령 응답으로 새 상태를 덮지 않도록 처리합니다.

적응형 조명은 기존 색온도 조명에서 사용합니다. 주기적으로 클라우드 명령이 발생하며 꺼진 조명에도 색온도 설정 요청이 생길 수 있습니다. 수동 색온도 변경이나 실제 컬러·장면 모드 전환은 자동 조명을 해제하고, 정상 명령의 상태 재수신과 구분합니다. 사용하지 않는 이전 색상이나 장면 정보가 함께 수신됐다는 이유만으로 자동 조명을 끄지 않습니다. 재탐색과 종료 시 저장된 예약을 유지하도록 로컬 검증했습니다. 실제 Home 앱에서 활성 예약의 두 차례 재시작 확인은 별도 검증 사항입니다.

## 전력 측정

확인된 모델에만 전력·전류·전압·누적 전력량을 설정합니다. **도움말 → 전력 측정 고급 설정**의 표에서 모델별로 행을 추가하거나 삭제합니다. 현재 연결 범위에 있는 장치의 모델을 선택하거나 직접 입력할 수 있습니다. 모델 이름은 실제 `modelName`과 정확히 같아야 하며, 저장한 설정은 같은 모델에서 지원되는 측정 항목에만 사용됩니다. 모델을 선택하는 것만으로 측정 기능이나 배율이 확인되는 것은 아닙니다.

표의 첫 줄은 기울임체로 표시한 가상의 참고 예시로, 저장되지 않습니다. 새 행에는 확인한 값만 입력하세요. 원본 항목은 장치가 보내는 값의 이름이며, 배율은 그 숫자를 표시 단위로 바꾸기 위해 곱하는 값입니다. 예를 들어 원본 `2200`에 `0.1`을 곱하면 `220 W`입니다. 전압은 V, 전류는 A, 누적 전력량은 Wh로 맞춥니다(`1250 Wh = 1.25 kWh`). 설정하지 않을 측정 항목은 원본 항목과 배율을 둘 다 비워 둡니다.

넓은 표는 아래 **표 가로 이동** 막대나 키보드로 좌우 이동할 수 있습니다. 저장 전에는 모델 중복, 누락된 항목, 0 이하이거나 유효하지 않은 배율을 확인합니다. 원본 JSON 편집은 **전문가용 원본 설정**에서 사용할 수 있습니다. 원본을 수정하는 동안 표 입력은 잠시 잠기며, **원본을 표에 적용**을 눌러 편집을 이어가거나 설정을 바로 저장할 수 있습니다.

모델마다 숫자의 단위가 다를 수 있습니다. 다음은 설명용 설정이며 실제 모델의 보정값이 아닙니다.

```json
[
  {
    "model": "EXAMPLE-MODEL",
    "power": { "field": "curPower", "multiplier": 0.1 },
    "current": { "field": "curCurrent", "multiplier": 0.001 },
    "voltage": { "field": "curVoltage", "multiplier": 0.1 },
    "energy": { "field": "measuredTotalWh", "multiplier": 1 }
  }
]
```

배율은 원본 값을 W, A, V, 누적 Wh로 바꾸는 값입니다. `measuredTotalWh`는 예시이므로 실제 누적 측정 항목이 있을 때만 설정합니다. 누적값이 없으면 전력을 적분해 사용량을 추정하지 않습니다. 잘못되거나 오래된 측정값을 0으로 표시하지 않습니다. 누적 전력량 보고는 최대 60초에 한 번으로 합치며 마지막 값도 전달합니다.

전력 측정이 설정된 단일 플러그에서는 전원이 켜진 상태와 실제 부하가 있는 상태를 구분합니다. 현재 기본 판정은 1W 이상 켜짐, 0.5W 이하 꺼짐이며 변경이 2초 이상 유지되는 측정 보고를 받으면 반영합니다. 처음부터 애매하거나 측정이 오래되면 확인할 수 없는 상태로 둡니다. 이 기준은 제조사 규격이 아니므로 낮은 전력을 쓰는 기기는 실제 사용량과 비교해 확인해야 합니다.

## 공기청정기와 PM2.5 측정

`Airpurifier`는 Apple Home과 Matter에서 전원을 제어하고, 설정 화면에서 자동·수동·취침 모드를 선택할 수 있습니다. 기기가 알려준 전원과 모드도 함께 표시합니다. 필터 수명·교체 알림·초기화와 풍량 제어는 제공하지 않습니다.

PM2.5는 기본적으로 표시하지 않습니다. 해당 모델의 원본 측정값과 단위를 확인했다면 장치별 **고급: PM2.5 측정값 보정**에서 배율을 설정할 수 있습니다.

1. 기기가 보내는 원본 값에 어떤 배율을 곱해야 µg/m³가 되는지 확인합니다. 모델이나 숫자의 모양만으로 배율을 정하지 마세요.
2. 확인한 양수 배율을 입력하고 저장한 뒤 Homebridge를 다시 시작합니다.
3. 장치별 연결 선택에 따라 Apple Home·Matter 또는 양쪽에 읽기 전용 PM2.5 항목이 추가됩니다. 새 측정값이 수신되면 값을 확인할 수 있습니다. 배율을 지우고 재시작하면 측정 항목만 제거되고 기존 전원 항목은 유지됩니다.

보정된 0~1000 µg/m³만 표시합니다. 값이 없거나 잘못됐거나 유효 시간이 지나면 정상값 또는 0으로 대신하지 않습니다. 좋음·나쁨 등의 등급도 계산하지 않습니다. Apple Home과 Matter는 같은 명시 보정값과 측정값 유효 시간 기준을 사용합니다.

Matter PM2.5는 재시작 뒤 측정 연결을 다시 준비할 수 있습니다. 연결된 앱에서 PM2.5 표시와 자동화를 확인해 주세요.

## 측정값 유효 시간

새 보고를 오래 받지 못한 숫자는 과거 측정값일 수 있습니다. 장치별 **측정값 유효 시간(분)**을 비워 두면 다음 자동 기준을 적용합니다.

| 측정 항목 | 자동 기준 |
| --- | --- |
| 온습도 센서·보정 PM2.5 | 90분 |
| 전력·전류·전압·누적 전력량 | 5분 |

필요하면 5~1440분 사이의 정수로 변경할 수 있습니다. 기본 시간은 플러그인이 값을 표시할 때 사용하는 여유 기준이며, 모든 장치가 그 간격으로 보고한다고 보장하는 값은 아닙니다.

유효 시간은 새 측정 보고를 받은 시각부터 계산합니다. 서버의 장치 목록을 다시 읽는 것만으로 측정 시각을 새로 만들지 않습니다. 따라서 재시작 직후 이전 숫자가 저장되어 있어도 새 보고가 오기 전에는 측정값을 확인할 수 없을 수 있습니다.

이 시간 설정은 문 열림·모션 같은 이벤트 상태나 배터리를 자동으로 정상·미감지로 바꾸지 않습니다. 측정값이 오래됐다는 이유만으로 기기 전체를 오프라인이라고 단정하지도 않습니다.

## 도어락의 문 열림 상태

`ZigbeeDoorlock`이 알려주는 문 열림 값만 Apple Home과 Matter에 읽기 전용으로 제공합니다. 문이 닫혔다는 것과 잠겼다는 것은 다릅니다. 잠금 상태를 추정하지 않으며 잠금·해제 명령은 보내지 않습니다. 문 열림 값이 없거나 확인되지 않으면 닫힘으로 대신하지 않습니다. 다른 도어락 타입에 이 기능을 자동으로 적용하지 않습니다.

## 이전 버전과 달라지는 표시

이전 버전에서 에어컨 온도조절기나 스마트 버튼 자동화 항목이 보였더라도, 실제 상태·이벤트가 확인되지 않으면 이번 버전에서는 해당 서비스를 제거합니다. 에어컨은 전원 제어와 설정 화면의 조작을 사용합니다. 해당 항목을 자동화에 연결해 두었다면 업데이트 후 동작과 설정을 확인해 주세요. 장치의 식별자는 유지하지만 제공되는 서비스가 달라질 수 있습니다.

## 현재 제공하지 않는 기능

다음은 장치 이름이나 Homebridge API만으로 지원을 약속하지 않습니다.

- 스마트 버튼의 단일·더블·길게 누르기 자동화: 실제 이벤트 종류 확인 필요.
- 레이더의 지속 재실 감지: 움직임 보고와 지속 재실 의미 확인 필요.
- 커튼 정지·각도 조절: 모델별 실제 명령 확인 필요.
- 배율을 확인하지 않은 공기질 측정과 공기질 등급, 공기청정기 필터·풍량 기능: 해당 측정·명령 계약 확인 필요.
- RGBW 색온도·장면 프리셋: 해당 모델의 실제 제어 기능 확인 필요.
- 카메라 영상·녹화, 도어락 잠금/해제, 보안 시스템 제어: 별도 장치 계약과 통합 검증 필요. 카메라 연결을 위한 내부 준비 코드가 있어도 사용자 영상 기능은 아직 제공하지 않습니다.

공개된 웹 코드에서 확인한 명령과 로컬 테스트를 실물 검증과 구분합니다. 현재 확인 가능한 헤이홈 등록 장비는 릴레이·RGBW 조명·벽 스위치·모션 센서이며 다른 제품군의 실기 결과는 아직 없습니다.

## Homebridge UI 6 자동화

UI 6 알파의 조명 그룹, 문 열림 감시, 습도 제어, 평균 온도, 보안 시스템 코드를 별도로 검증했습니다. 일부 규칙은 오래된 센서값이나 응답 없는 센서를 안전하게 처리하지 못합니다. 실행 코드 검증과 실제 자동제어의 안전성을 구분해야 합니다.

[자동화 사용 전 확인 사항과 예시](smart-automation-guide.md)를 확인해 주세요. Hejhome 베타를 사용하기 위해 UI 알파를 설치할 필요는 없습니다.

## 정식 버전으로 돌아가기

1. 새 연결 옵션을 끄고 저장한 뒤 플러그인을 다시 시작합니다. 명시적으로 끄거나 숨긴 연결은 클라우드 조회 성공과 별개로 정리합니다.
2. 더 이상 쓰지 않는 별도 Matter 연결은 스마트홈 앱에서 제거합니다. 기존 Apple Home 연결은 유지합니다.
3. Homebridge 플러그인 메뉴에서 정식 버전을 선택하거나 같은 설치 환경에 `@chazepps/homebridge-hejhome@latest`를 설치합니다.
4. 2.0 버전으로 돌아갈 때는 Hejhome 설정의 `features` 항목을 제거합니다. 이전 버전은 새 항목을 알지 못합니다.
5. 다시 시작하고 장치를 확인합니다. 일반적인 복귀 과정에서 액세서리를 초기화할 필요는 없습니다.

## 출시 담당자 확인 사항

- 기능 체크리스트의 코드 완료·로컬 검증·실기 검증·게시 상태를 구분한다.
- 전체 검증과 패키지 검사를 통과한 뒤 별도 게시 지시를 받는다.
- package/lockfile 버전과 `v3.0.0-beta.N` 태그를 일치시키고 `publishConfig.tag=beta`를 유지한다.
- 게시 전에 release channel 검사 결과가 `beta`인지 확인한다.
- 게시했다면 npm `beta`와 `latest`를 직접 조회해 채널이 분리됐는지 확인한다.
- 정식 승격은 별도 릴리스로 처리한다. 이번 준비에서 게시나 운영 변경은 하지 않는다.
