# Hejhome 2.1 beta guide

Status: local release candidate; not published. The installation commands below apply only after a maintainer explicitly publishes this beta.

## Installation and isolation

The plugin beta is separate from Homebridge core beta. Use Homebridge 2.4+ stable and UI 5.29+; Node 22.12+, 24 or 26. Homebridge 1 users remain on plugin 2.0.x. In Homebridge UI select the plugin's alternate version / beta release, or install the explicit npm dist-tag in the same installation environment as the running bridge:

```sh
npm install -g @chazepps/homebridge-hejhome@beta
```

A plain install/update of `@chazepps/homebridge-hejhome` follows `latest`, which stays on the stable release. This branch is `2.1.0-beta.0`, and both package publishConfig and the release workflow select `beta`. No tag has been pushed and no registry changes are made by preparation.

## Feature setup

After logging in, open **2.1 베타 기능**. Both switches default off. Save and restart the plugin child bridge.

- **Matter 장치 노출**: also enable Matter on this plugin's child bridge in Homebridge UI. Pair its Matter QR in the desired controller. Use working LAN IPv6/mDNS. Retain the HAP pairing if desired; pairing both protocols to the same Home app creates duplicate representations. Matter remains dependent on Hejhome cloud, and does not add Thread radio or offline device control. Homebridge Matter is an uncertified community implementation.
- **적응형 조명**: enable Adaptive Lighting for a `LightWw1/2/3` light in Apple Home as well. Brightness and colour-temperature ranges are taken from the existing Hejhome mapping (3000–6500 K). The automatic controller calls the cloud periodically, including while a lamp is off. Writes are coalesced for 350 ms. A manual temperature report outside a recent command echo disables the schedule. Schedules use Homebridge's persisted controller state.
- **계측 프로필 JSON**: only enter a model name and units established from the device's actual telemetry. Profiles are exact `modelName` matches, not broad device-type guesses. Measurements are read-only. Omit unsupported quantities.

Example profile (illustrative, not a calibrated real model):

```json
[
  {
    "model": "EXAMPLE-MODEL",
    "power": { "field": "curPower", "multiplier": 0.1 },
    "current": { "field": "curCurrent", "multiplier": 0.001 },
    "voltage": { "field": "curVoltage", "multiplier": 0.1 },
    "energy": { "field": "measuredTotalWh", "multiplier": 1 }
  }
]
```

Each multiplier converts the raw state field to W, A, V or cumulative Wh. The adapter then converts to Matter mW, mA, mV and mWh. `measuredTotalWh` is only an example: configure an actual cumulative field if the model provides one. Missing, negative, malformed and non-finite data stay unknown. Zero remains a valid reading. There is no estimated energy integration. Changed energy reports are coalesced to at most once per 60 seconds, including delivery of the last pending reading. Controller support determines whether measurements are displayed.

## Matter support in this beta

| Device class | Matter mapping |
| --- | --- |
| Relay, safe IR power control | On/off light actuator (not a controller-only switch) |
| Wall switches, power strips | Stable per-datapoint composed parts; strip all-off field excluded |
| Plug | On/off outlet; optional calibrated electrical measurement |
| RGB/RGBW/strip | Hue/saturation and brightness; no unsupported temperature or XY commands |
| White light | Brightness and colour temperature |
| Curtain/blind | Lift position; HomeKit open percentage inverted to Matter closed percentage |
| Motion/contact/leak/smoke | Corresponding sensor; missing boolean readings mark unreachable |
| Temperature/humidity | Composed temperature and humidity parts with nullable hundredth-unit readings |
| Battery | PowerSource when a battery field is present |

Continuous dimming, curtain stop, IR HVAC mode translation, stateless-button gesture timing, locks and camera streams are not claimed as Matter capabilities in this beta: their Hejhome command/event contracts need device evidence. Existing HAP mappings remain. RGB devices without a demonstrated colour-temperature field do not get Adaptive Lighting. A Matter-capable core does not make these vendor capabilities available automatically.

## Rollback

Disable the beta feature switches, save and restart once so the adapter can remove its Matter registrations after successful cloud discovery. Remove the separate Matter pairing in the controller if no longer needed. Keep existing HomeKit pairing data. Select the stable plugin version in Homebridge UI, or install `@chazepps/homebridge-hejhome@latest` in the same environment. Remove the `features` property from the Hejhome platform config when returning to 2.0.x, whose strict schema does not know it. Restart. Do not reset HAP accessories as a normal rollback step.

## Pre-publication acceptance

Local checks validate API contracts and endpoint conformance, not physical-device behavior. Before publishing, validate on a dedicated child bridge: actual Matter commissioning; commands and external MQTT updates in both controllers; two restarts with preserved endpoint identity and working handlers; relays/multi-gang targeting; curtain direction; white-light schedule and manual override; actual meter units against the vendor app; deliberate cloud failures; rollback without HAP identity changes. No operational bridge is modified by this task.

## Maintainer release procedure

1. Run full verification and package inspection on this branch. Record device acceptance evidence.
2. For each later beta, change both package versions to `2.1.0-beta.N`, retaining `publishConfig.tag=beta`.
3. Review `node tools/release/channel.mjs v2.1.0-beta.N` (must print `beta`).
4. Only after explicit publication approval, push the matching release tag. Workflow validation and supported-Node checks must pass before Trusted Publishing runs.
5. Confirm npm `beta` points to the intended prerelease and `latest` still points to the prior stable version. A stable promotion is a separate reviewed release: remove the prerelease suffix and deliberately change publishConfig.tag to `latest`.
