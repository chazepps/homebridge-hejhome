# 2.1.0 beta implementation plan

**Goal:** Prepare an opt-in beta with Matter, Adaptive Lighting, calibrated metering and current runtime compatibility without publishing.

**Spec:** `docs/design-docs/2.1.0-beta.md`

**Architecture:** Share cloud state; add host-API Matter and Adaptive Lighting adapters. Separate executable publishing policy from runtime feature settings.

## Tasks and validation

- [ ] Release isolation: test beta/stable/mismatched tags in tests/release-channel.test.ts; implement tools/release/channel.mjs; set 2.1.0-beta.0/default beta tag; add Node 26 and stable/beta host CI.
- [ ] Matter and metering: test relay datapoints, composed endpoints, light features, sensor units, covering inversion, restoration/removal, failures, explicit meter units/cadence; implement adapter modules and shared successful state.
- [ ] Adaptive Lighting: test opt-in white-light controller, manual changes versus echoes, coalescing and disposal; integrate with HAP.
- [ ] Settings/docs: test save/reload preservation, validate options and meter profiles; expose UI/schema; document installation/rollback.
- [ ] Verification: npm run verify, package dry run and tarball inspection, release-policy dry run, independent code review. Record physical-device acceptance as pending.

## Review focus

Never overwrite latest with a prerelease; preserve HAP UUIDs and _bridge config; never recursively acquire a Matter transaction; do not infer raw meter units; cancel adaptive timers; failed discovery must preserve cached devices.

## Execution notes

User authorized the implementation and prohibited publication. Implement inline; no release tags, publishing or production changes.
