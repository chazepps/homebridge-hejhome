# 2.1.0 beta implementation plan

**Goal:** Prepare an opt-in beta with Matter, Adaptive Lighting, calibrated metering and current runtime compatibility without publishing.

**Spec:** `docs/design-docs/2.1.0-beta.md`

**Architecture:** Share cloud state; add host-API Matter and Adaptive Lighting adapters. Separate executable publishing policy from runtime feature settings.

- [x] Release isolation: test beta/stable/mismatched tags in tests/release-channel.test.ts; implement tools/release/channel.mjs; set 2.1.0-beta.0/default beta tag; add Node 26 and stable/beta host CI.

## Deliberate boundaries

Meter units are explicit per-model configuration because no universal calibration is evidenced. Unsupported vendor commands (continuous dimming, blind stop, IR HVAC modes, button timing, locks, cameras) are not invented. This implements the researched technologies on supported capabilities; it is not a claim that every vendor model supports every new feature.

Physical commissioning, calibrated meter comparison, active Adaptive Lighting schedule persistence over two actual bridge restarts, cloud outage behavior and physical rollback remain pre-publication acceptance checks in the beta guide. This preparation does not publish, push release tags, or alter npm dist-tags. CI configuration is validated locally; no GitHub Actions run is claimed without a push.
