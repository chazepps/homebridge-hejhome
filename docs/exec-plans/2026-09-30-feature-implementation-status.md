# Homebridge 기능 확장 구현·검증 기록

작성일: 2026-09-30. 대상: `codex/hejhome-2.1.0-beta`, `2.1.0-beta.1` 로컬 후보.

[전체 액션 체크리스트](2026-09-30-homebridge-feature-action-checklist.md)의 완료 표시는 이 기록을 근거로 한다. 155개 항목을 모두 완료한 것으로 표시하지 않는다. 코드를 구현한 범위, 코드로 검증한 범위, 실제 기기 계약이 없어 구현하지 않은 범위를 구분한다.

## 실행 환경과 작업 경계

- 사용자 요청에 따라 7개 서브에이전트가 서로 다른 파일 영역을 병렬 구현했고, 비작성자가 영역별 독립 리뷰를 수행했다.
- `czmm`에서 저장된 Homebridge 장비 목록과 설치 버전만 읽었다. 기기를 조작하거나 서비스·플러그인을 설치/재시작하지 않았다.
- 확인된 설치 버전: core 2.4.1-beta.11, UI 6.0.1-alpha.20, Hejhome 2.0.2.
- 저장된 장비 목록에는 릴레이 1개, RGBW 조명 1개, 벽 스위치 4개, 모션 센서 1개가 있다. 장치 이름·식별자·계정 없이 종류와 필드만 `tests/fixtures/czmm-capability-inventory-20260930.json`에 남겼다.
- 공개 공급자 웹 코드의 필드·단위 변환·명령 순서를 조사했다. 원본 UI 코드나 비밀을 배포 문서에 복사하지 않았다.
- `latest`/`beta` dist-tag, 운영 설치, 원격 설정을 변경하지 않았다.

## 중요한 구현 경계

### 공유 상태와 명령

`src/runtime/`는 상태·측정 신선도·필드별 관측 버전·진단 저장·로컬 명령 전달을 분리한다. `src/platform.ts`의 장치 저장소는 HAP 노출과 독립적이다. UI 리모컨도 같은 장치별 명령 대기열을 사용한다. 느린 응답보다 새 MQTT 관측이 우선이며, HAP/Matter 프레임워크의 쓰기 완료 이후에도 최신 상태를 유지하도록 검증했다.

UI 명령 전달은 해당 저장 공간의 제한된 Unix socket을 사용한다. 요청 크기·유효시간·동일 요청 재전송을 제한하고 다른 프로세스의 활성 socket을 삭제하지 않는다. 종료는 대기 명령을 취소하며 자동 재전송하지 않는다. Windows의 새 UI 리모컨 경로와 너무 긴 socket 경로는 준비 불가로 표시한다. 기존 HAP/Matter 경로와 분리된 제한이다.

### 검증되지 않은 상태를 만들지 않기

현재 온도와 설정 온도, 릴레이 전원과 실제 부하, 명령 전송과 물리 동작을 구분한다. 미등록 기기를 임의 relay로 만들지 않는다. ID 없는 캐시는 추측해 삭제하지 않는다. 피드백 없는 IR은 순간 버튼으로 처리하며, Matter 절대 전원 장치로 가장하지 않는다.

에어컨의 공통 웹 명령은 확인됐지만 필수 실제 운전 상태가 없다. 항상 오류를 내는 온도조절기 서비스를 노출하는 대신 확인된 전원과 설정 화면 조작을 제공한다. 기존 자동화가 해당 서비스에 연결되어 있다면 사용자 안내에 따라 변경 영향을 확인해야 한다.

### 자동화는 호스트 알파의 한계까지 기록

공식 UI 태그 `v6.0.1-alpha.20`, commit `b85d97ff3777c6f72a451db9ba8c16bd530fab42` 기준이다. 규칙을 복제하지 않고 그 소스를 별도 환경에서 실행했다.

- C1: 개별 조명 변경의 그룹 표시 역반영이 없다.
- C2/C3: 마지막 센서값의 나이·오류 상태를 규칙 자체가 검사하지 않는다.
- C4: 모든 입력 읽기가 실패해도 가상 센서가 마지막 평균값을 유지한다.
- C5: 입력 센서를 찾지 못해도 경계를 허용할 수 있다.

이 결과를 안전 호환성 통과로 표시하지 않는다. [고객 가이드](../product-specs/smart-automation-guide.md)에 각 제한과 확인 방법을 기록했다.

## 리뷰와 수정 근거

각 구현자와 다른 작업자가 runtime, HAP, Matter, UI/config, IPC를 검토했다. 중요한 결함은 재현 테스트를 추가한 뒤 수정했고, 원인과 수정 결과를 작업 보고에 남겼다. 대표 사례는 다음과 같다.

- 세션 교체 후 이전 장치 접근, 실패한 재탐색 삭제, reconnect 중 놓친 변경 복구.
- 헤더 수신 후 응답 본문 무한 대기와 세션 교체 시 HTTP 취소.
- 느린 REST 응답이 최신 MQTT 값을 덮는 문제 및 서로 무관한 필드 충돌 구분.
- Adaptive Lighting 제거가 저장 예약을 지우는 문제와 실제 ControllerStorage 복원.
- 실제 HAP 순간 버튼이 완료 뒤 켜짐으로 되돌아가는 문제.
- 연속 조광 재시작으로 요청 예산을 우회하거나 지연된 자체 보고를 사용자 조작으로 오인하는 문제.
- 만료된 부하 상태가 애매한 새 측정으로 정상 상태처럼 되살아나는 문제.
- 실시간 진단 갱신이 입력 중 설정을 지우는 문제, 원본 계측 편집/삭제 무시, 과거 기록의 제어 버튼 활성화.
- 서로 다른 설정 저장 경로의 검증 우회, 등록 준비와 실제 앱 연결의 문구 혼동.
- 밝은 테마 배지 대비 부족: 브라우저 계산 기준 4.5:1 이상으로 보완.

## 로컬 검증 기록

- Node 24.4.1 / Homebridge 2.4.0에서 최종 `npm run verify` 통과: 40개 파일의 코드 테스트 287개, Playwright 테스트 26개, lint/typecheck/build/docs 검사. 로그: `/tmp/hej-beta1-release-verify.log`.
- 같은 최종 코드의 전체 테스트 287개가 Node 22.12.0과 Node 26.10.0에서도 각각 통과했다. 로그: `/tmp/hej-beta1-node22-final.log`, `/tmp/hej-beta1-node26-final.log`.
- 실제 tarball을 별도 임시 환경에 설치하고 Homebridge 2.4.1-beta.11에서 12개 장치 계열의 Matter 등록·복원을 Node 22/24/26으로 확인했다. 이는 베타 호스트의 패키지 smoke test이며 전체 운영·페어링 인수를 대체하지 않는다.
- 패키지의 로컬 명령 전달도 별도 환경에서 정상·거부 요청을 확인했다. 실제 공급자 명령 전송은 0건이다.
- 공식 자동화 소스 probe는 C1–C5 실행을 확인하며 위 LIMITATION을 함께 출력한다. 수정된 별도 clone에서도 immutable Git blob만 사용하는지 확인했다.
- 한국어/영어·밝은/어두운 테마·375/1200px 화면과 입력 포커스·대비를 테스트하고 생성 화면을 검토했다.
- `node tools/release/channel.mjs v2.1.0-beta.1`은 `beta`를 반환한다. package/lockfile과 `publishConfig.tag=beta`가 일치한다.
- `npm pack --dry-run` 및 실제 tarball 내용 검사를 완료했다. 101개 파일, 756,112 bytes이며 컴파일된 기능과 사용자 가이드를 포함한다. 소스 테스트 fixture·개인 작업 기록·세션·계정 설정은 포함하지 않는다.
- 패키지: `chazepps-homebridge-hejhome-2.1.0-beta.1.tgz`. SHA-256: `8ae3c3bc88dcccc9ea20d29d900d35469ce1621ca92018f3915dd159befd1947`.
- 작업 종료 전 czmm의 Hejhome 설치 버전이 기존 2.0.2 그대로임을 다시 확인했다.
- 실제 기기 제어, 실제 Home 앱/Matter 페어링, 운영 설치·재시작, npm 게시·태그 push는 수행하지 않았다. GitHub CI 실행과 실제 정식 버전 복귀 인수도 남아 있다.

## 남은 작업을 끝내는 데 필요한 근거

버튼·팬 단계·레이더 재실·커튼 정지/각도·공기질·카메라·잠금 기능은 해당 모델의 비식별 실제 보고/명령 응답, 단위·동작 의미가 필요하다. 현재 등록된 7개 장비로 얻을 수 없는 데이터를 추정하지 않는다. 카메라와 잠금은 불완전한 틀만 추가해 구현 완료로 표시하지 않았다.

코드로 검증 가능한 공통 기능은 구현했으나, 열린 체크박스는 아직 해결되지 않은 실제 조건이다. 별도 장비나 공급자 계약이 확보되면 같은 ID의 항목에서 이어서 진행한다.
