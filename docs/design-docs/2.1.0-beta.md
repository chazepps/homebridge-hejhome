# 2.1.0 beta design

## Contract

Prepare `2.1.0-beta.0` on `codex/hejhome-2.1.0-beta`. Do not publish, push a release tag, install on a live bridge, or modify npm dist-tags. Users explicitly select npm `beta`; existing `latest` installations remain on 2.0.x. Publication defaults to beta and automation validates version, lockfile, tag and channel.

## Runtime

Require Homebridge 2.4+ and Node 22.12+, 24 or 26. Preserve HAP UUIDs and cloud authentication. Matter and Adaptive Lighting are independently opt-in and disabled by default. Matter also requires the host bridge setting. Use the public host API, without a direct matter.js dependency.

The Matter adapter owns registration, cache restoration, features, composed outlets/switches/sensors, command translation and realtime state updates. Unknown/deferred devices never become invented controls. Both protocols share successful cloud-command state and MQTT updates. Await commands and propagate failures. Never update Matter state from inside its command transaction. Restore handlers and remove stale endpoints only after complete successful discovery.

Adaptive Lighting targets white-light models with verified brightness/temperature commands. HomeKit owns the schedule; writes are coalesced. External manual changes disable it; matching command echoes do not. Cancel timers on removal/shutdown. RGB-only models do not acquire invented colour-temperature support.

Meter profiles explicitly specify per-model source fields and multipliers in W/A/V/Wh: raw Hejhome meter units are not documented per model. Missing/non-finite readings stay unknown, never zero. Energy needs a real cumulative source; never integrate estimated power. Convert to Matter milli-units, deduplicate and throttle energy to 60 seconds. Metering is read-only.

## UI and release

Expose beta options in the custom settings UI while preserving login, scope and bridge config. Document beta installation, pairing, HAP/Matter independence, duplicate-device avoidance and rollback. Test Node 22/24/26 and stable/beta Homebridge. Plugin beta does not require core beta or UI alpha.

## Acceptance

Test release rejection, Matter mapping/commands/cache/removal/errors, Adaptive Lighting lifecycle, metering units/missing data/cadence, UI persistence, complete verify and package inspection. Physical commissioning and actual meter calibration remain explicitly unverified until tested on hardware before publication.
