# Hejhome 현재 베타 UI 재설계 실행 명세

> 이 문서는 다른 LLM이 기존 대화를 읽지 않고 UI 재설계를 수행하기 위한 단일 작업 지시서다. 문서 작성 자체는 구현·게시·운영 변경 지시가 아니다. 사용자가 이 문서를 실행 지시와 함께 전달했을 때 아래 범위로 작업한다.

## 1. 목표와 기준

현재 구현된 Hejhome 베타 기능을 고객이 쉽게 찾고 설정할 수 있도록 Homebridge 플러그인 설정 화면을 다시 설계한다. 핵심은 **내 장치 → 필요한 조작 또는 설정 → 결과 확인**이다.

- 저장소: `/Users/chaz/work/homebridge-hejhome`
- 문서 작성일: 2026-09-30
- 작성 시 읽기 전용으로 확인한 버전: `3.0.0-beta.1`
- 이전 논의의 `2.1.0-beta.1`은 현재 버전 기준으로 사용하지 않는다. 착수 시 `package.json`, 실제 코드와 테스트를 다시 확인한다.
- 기능 목록은 실행 시점의 코드가 기준이다. 문서에 빠졌다는 이유로 이미 구현된 기능을 삭제하지 않는다.
- 이번 작업은 UI 정보 구조, 사용자 흐름, 표현, 접근성, 반응형 화면 개선이다. 새 기기 지원이나 공급자 명령을 추가하는 작업이 아니다.

사용자는 기능 목록이 길게 나열된 개발자 화면이 아니라, 일반 고객이 이해할 수 있는 완성도 높은 화면을 원한다. 구현되지 않은 기능을 메뉴·버튼·예시 데이터로 실제 사용할 수 있는 것처럼 보이게 하지 않는다.

## 2. 작업 경계

### 포함

- 로그인과 재로그인 흐름의 화면 정리.
- 내 장치 목록, 장치 상세, 지원되는 조작과 장치별 설정.
- 계정, 집·방, 연결 앱, 자동 조명 설정의 재배치.
- 연결 상태, 오류 안내, 진단과 지원 정보의 단계적 노출.
- 한국어·영어, 밝은·어두운 테마, 작은 화면, 키보드 사용.
- UI 테스트 보강과 화면 렌더링 확인.

### 제외

- 새 장치 기능, 프로토콜, 공급자 API, 자동화 엔진 구현.
- 버전 변경, 의존성 일괄 업데이트, 임의 프레임워크 도입.
- npm 게시, 릴리스 태그, push, 운영 서버 설치·재시작·설정 변경, 실제 장치 조작.
- 무관한 파일 정리, 다른 작업자의 변경 되돌리기, 캐시나 페어링 초기화.

별도 지시가 없으면 현재 체크아웃에서 필요한 파일만 변경하고 결과를 남긴다. 기존 브랜치를 임의로 바꾸거나 새 작업을 다른 대화에 보내지 않는다.

## 3. 먼저 읽을 구현과 계약

| 파일 | 확인할 내용 |
| --- | --- |
| `homebridge-ui/public/index.html` | 기존 화면, 상태 관리, 다국어·테마, 명령 준비 조건, 입력 보존 |
| `homebridge-ui/server.js` | 요청 경로, 장치 소유·유형 검증, 저장·진단 계약 |
| `src/features.ts` / `config.schema.json` | 저장 형식, 기본값, 유효성 검사 |
| `src/runtime/status.ts` / `src/runtime/commands.ts` | 진단 정보의 의미와 기존 명령 전달 경로 |
| `src/devices/capabilities.ts` | 실제 지원 범위와 조건부 서비스 |
| `tests/ui/` 및 UI 서버 테스트 | 보존해야 할 동작과 현재 검증 방식 |
| `package.json` / `docs/FRONTEND.md` | 실행 명령과 Homebridge custom UI 제약 |

작성 시 확인된 요청 경로는 다음과 같다. 재설계에서 기존 서버 계약을 재사용한다.

- 인증: `/send-verification`, `/verify-code`, `/login`, `/logout`, `/session-status`
- 저장: `/save-scope`, `/save-features`, `/save-device-settings`
- 상태: `/diagnostics`, `/diagnostics-export`
- 조작: `/remote-command`, `/air-conditioner-command`, `/purifier-command`
- 내부 기록: `/ui-event`

작성 시 장치별 설정에는 `visibility`, `name`, `role`, `temperatureSensorId`, `freshnessMinutes`, `remoteButtons`, `pm25Multiplier`가 있다. 전역에는 Matter, 자동 조명, 전력 측정 모델 설정이 있다. 각 필드의 적용 대상과 기본값을 코드에서 확인해 유지한다. 모든 장치에 모든 필드를 보여주지 않는다.

## 4. 정보 구조: 세 개의 주 화면

로그인 전에는 로그인 화면을 사용한다. 로그인 이후 첫 화면은 **내 장치**다.

```text
Hejhome                                      베타
현재 연결 상태 또는 필요한 조치 한 줄

[ 내 장치 ]  [ 연결 설정 ]  [ 도움말 ]

선택한 화면의 내용
```

- 세 화면은 Homebridge 플러그인 설정 영역 안에서 전환한다. 별도 앱이나 외부 대시보드를 만들지 않는다.
- 별도의 큰 홈 대시보드나 중복 장치 목록을 추가하지 않는다.
- 상태·설정·지원 정보는 같은 장치 ID에 연결한다. 같은 장치를 서로 독립적인 두 목록으로 관리하지 않는다.
- 저장 상태와 재시작 안내는 실제 해당 작업에 가까운 위치에 표시한다.
- 탭 전환과 장치 상세 진입·복귀에서 입력 초안, 포커스, 목록 위치를 보존한다.

## 5. 로그인과 계정 상태

### 첫 로그인

- 이메일 입력 → 인증번호 확인 → 비밀번호 입력의 순서를 명확히 보여준다.
- 이전 단계를 마치기 전에 다음 작업을 실행할 수 없도록 기존 검증을 유지한다.
- 현재 단계의 입력과 주요 버튼을 강조한다. 나중에 사용할 비활성 입력을 한꺼번에 크게 펼치지 않는다.
- 항상 켜지는 자동 로그인은 변경할 수 없는 체크박스 대신 간단한 설명으로 표현할 수 있다. 저장·인증 동작은 바꾸지 않는다.
- 비밀번호·인증번호를 장치 설정이나 브라우저 영구 저장소에 새로 보관하지 않는다.

### 재로그인

- 저장된 장치와 설정을 지우지 않고 “로그인이 만료됐어요. 다시 로그인해 주세요.”와 행동 버튼을 보여준다.
- 로그인 문제를 장치가 삭제된 상태로 표현하지 않는다.
- 정상 계정에는 큰 성공 카드나 로그아웃 버튼을 계속 강조하지 않는다. 계정 관리는 연결 설정에서 제공한다.

## 6. 내 장치

### 목록

각 장치에는 다음 정보만 기본 노출한다.

1. 사용자가 알아보는 이름.
2. 쉬운 장치 종류.
3. 현재 코드로 확인 가능한 상태 한 줄.
4. Apple Home/Matter 사용 준비 상태 또는 확인이 필요한 사유.
5. 상세 진입 버튼, 해당 장치에 실제 구현된 경우에만 조작 진입 버튼.

목록에서 이름·앱·형태·보정값을 모두 편집하게 하지 않는다. 이름 검색과 “전체 / 확인 필요 / 표시하지 않는 장치” 같은 필터는 현재 데이터로 정확히 만들 수 있는 범위에서 제공한다. 현재 응답에 없는 방 이름이나 실측값을 만들어 그룹화하지 않는다.

### 장치 상세

같은 설정 영역 안에서 상세 화면 또는 펼침 영역을 연다. 모바일에서는 세로 흐름과 명확한 “장치 목록으로” 동작을 제공한다.

- **장치 조작**: 현재 구현된 기능만 표시.
- **표시 설정**: 이름, 연결할 앱, 허용되는 표시 형태.
- **장치에 맞는 추가 설정**: 실제 온도계 연결, 상태 확인 시간, 리모컨 버튼 표시, 확인된 측정 보정 등 현재 지원 필드.
- **연결 상태 자세히**: 마지막 수신·전송 결과, 준비 상태와 필요한 안내.

표시 형태는 물리 장치 종류를 바꾸는 기능처럼 설명하지 않는다. 실제 적용되는 연결 방식의 범위도 명시한다. 기본 `both` 등 저장값과 전역 Matter 비활성 상태의 관계를 유지하고, Matter가 꺼져 있는데 두 앱에 이미 연결된 것으로 표시하지 않는다.

### 현재 구현된 조작 보존

- TV·셋톱박스: 현재 구현된 음량·채널·음소거 버튼.
- 선풍기: 현재 구현된 풍량·회전 버튼. 실제 단계나 회전 상태를 모르면 선택 상태를 만들어 표시하지 않는다.
- 에어컨: 현재 구현된 설정 온도·운전 방식·바람 세기. 실제 현재 온도와 설정 온도를 구분한다.
- 공기청정기: 현재 `/purifier-command`와 장치 능력 정보가 허용하는 조작·표시만 제공한다.
- 다른 모델도 실행 시점에 조작이 구현돼 있다면 보존한다. 모든 조명·스위치에 새 전원 버튼을 임의로 추가하지 않는다.

IR처럼 실제 전원 상태를 받지 못하는 장치는 “전원 버튼”으로 표현한다. `Fan`과 `Switch` 중 조건부로 하나를 쓰는 장치를 두 서비스가 동시에 제공되는 것처럼 표시하지 않는다.

## 7. 연결 설정

다음 순서로 배치한다.

1. **헤이홈 계정**: 로그인 상태, 다시 로그인, 로그아웃.
2. **가져올 장치**: 기존 집·방 선택.
3. **연결할 앱**: 기존 Apple Home 연결 안내, 다른 스마트홈 앱에 연결하는 Matter 설정.
4. **조명 색 자동 조절**: 지원되는 조명에서 사용하는 Adaptive Lighting 설정과 Home 앱에서 필요한 후속 작업.

- “베타 기능”이라는 큰 범주로 서로 다른 설정을 모으지 않는다. 용도별로 배치하고 베타 표시는 헤더에 간결하게 유지한다.
- 기존 전역 설정의 기본값·옵트인 조건을 유지한다.
- Matter 켜기만으로 앱 연결이 끝났다고 표시하지 않는다. 현재 코드가 제공하는 후속 연결 안내를 제공한다.
- 현재 제어할 수 없는 Homebridge 재시작 버튼이나 QR 생성 기능을 새로 약속하지 않는다. 제공 가능한 안내·이동 기능만 사용한다.

## 8. 도움말과 고급 설정

기본 내용:

- **연결 문제 확인**: 로그인, 장치 찾기, 상태 수신, 앱 연결 준비를 순서대로 설명.
- **지원하는 장치**: 실제 지원·일부 지원·확인 중인 기능 구분.
- **문제 신고용 정보**: 기존 비식별 진단 내용 보기·복사.
- **고급 설정**: 전력 측정 모델과 단위 보정, 현재 제공되는 고급 옵션, 전문가용 원본 편집.

전체 지원 모델 목록과 요청용 글을 기본 장치 화면 하단에 길게 펼치지 않는다. 사용자가 가진 미지원 장치에는 해당 이유와 도움말 진입을 제공한다. 아직 구현되지 않은 카메라·도어락 기능은 일반 메뉴의 빈 화면이나 동작하지 않는 버튼으로 늘리지 않는다.

원본 편집 기능을 보존할 경우 양식과 원본이 서로 다른 저장 상태가 되지 않도록 한다. 마지막 항목 삭제도 실제 빈 목록으로 저장돼야 한다. 개인정보가 없는 진단 내보내기 경계를 유지하고 자동 외부 전송을 추가하지 않는다.

## 9. 상태와 고객 문구

| 실제 의미 | 권장 표현 | 금지할 오해 |
| --- | --- | --- |
| 로그인 유효 | 로그인됨 | 전체 기기 동작이 정상이라는 보장 |
| 인증 만료 | 다시 로그인해 주세요 | 장치가 삭제됨 |
| 최신 상태를 확인하지 못함 | 최근 상태를 확인할 수 없어요 | 정상값 0·꺼짐·이상 없음 |
| Homebridge에 등록됐으나 앱 페어링은 미확인 | Apple Home용으로 준비됨 / Matter 연결 준비됨 | 앱 연결 완료 |
| 이전 캐시만 존재 | 이전에 저장된 장치 | 현재 연결 중 |
| 서버가 명령에 응답 | 명령 전송 완료 | 실물이 반드시 동작함 |
| 결과를 확인하지 못함 | 응답을 확인하지 못했어요. 기기 동작을 확인해 주세요. | 무조건 미전송이라고 단정하거나 자동 재전송 |
| 이름·연결 설정 저장 | 저장했어요. 다시 시작하면 적용돼요. | 저장 즉시 반영 완료 |
| 지원 범위 불명확 | 이 기능은 아직 확인되지 않았어요 | 사용 가능 |

- HAP, endpoint, cluster, snapshot, enum 같은 구현 용어를 일반 고객 화면의 주요 문구로 쓰지 않는다.
- Apple Home·Matter처럼 선택에 필요한 제품 이름은 사용하되 한 줄 설명을 붙인다.
- 한국어와 영어는 동일한 의미와 기능을 제공한다. 사용자 지정 장치 이름과 모델명은 임의로 번역하지 않는다.
- 문구는 짧게 쓰고, 설명을 길게 읽어야 하는 경우 상세나 도움말로 옮긴다.

## 10. 저장·실시간 갱신·제어 계약

- 즉시 실행되는 조작과 저장 후 적용되는 설정을 시각적으로 구분한다.
- 변경사항이 있는 설정 영역에만 저장 동작을 강조한다. 관련 없는 장치 설정을 함께 덮어쓰지 않는다.
- 저장 성공 전 초안을 지우거나 적용 완료로 표시하지 않는다. 저장 실패 시 입력과 재시도 기회를 유지한다.
- 실시간 상태 갱신은 사용자가 입력한 이름·선택·채널·온도, 커서 위치와 포커스를 덮지 않는다.
- 늦게 도착한 이전 응답이 새 상태나 저장 결과를 되돌리지 않도록 한다.
- 탭 전환 중 미저장 변경은 유지하고 표시한다. 실제로 버리는 동작에만 버림 의사를 확인한다.
- 제어 버튼의 활성화는 기존 `controlsAreReady` 등 준비·신선도·권한 조건을 그대로 사용한다. `controlsAvailable` 하나만 보고 활성화하지 않는다.
- 명령은 기존 서버 요청과 런타임 전달 경로를 사용한다. 브라우저 직접 공급자 요청이나 별도 REST 우회를 만들지 않는다.
- 시간 초과·연결 실패 때 명령을 자동 재전송하지 않는다. 특히 IR 버튼은 중복 동작할 수 있다.
- 기존 센서 보정·유효성 검사·노출 가능 모델 제한을 UI 편의 때문에 완화하지 않는다.

## 11. 시각·접근성 기준

- 기존 초록색 브랜드를 유지한다. 색상을 늘려 의미를 복잡하게 만들지 않는다.
- 이름과 주요 행동을 강조하고 설명·시각·고급 정보는 낮은 우선순위로 배치한다.
- 상단의 큰 소개 카드, 중복 숫자 카드, 반복 성공 표시를 줄인다.
- 정상 상태는 조용하게, 조치가 필요한 상태만 눈에 띄게 표시한다. 색상만으로 상태를 구분하지 않는다.
- 작은 본문·배지의 글자 대비는 두 테마에서 최소 4.5:1을 목표로 한다.
- 주요 터치 영역은 최소 44×44 CSS px을 목표로 하고, 버튼 간격과 키보드 포커스를 확보한다.
- 375px 폭에서 가로 스크롤 없이 사용 가능해야 한다. 고정 사이드바나 넓은 표를 모바일에 강제하지 않는다.
- 동작 가능한 항목은 button/link, 입력은 연결된 label을 사용한다. 탭은 키보드와 현재 선택 상태를 지원한다.
- 상태 갱신을 화면 전체의 반복 음성 알림으로 만들지 않는다. 필요한 상태 영역만 적절히 알린다.
- 모션은 짧고 기능적이며 reduced-motion 설정을 존중한다.
- Homebridge custom UI의 iframe·호스트 스타일·스크롤 높이·이벤트 정리 계약을 유지한다. `<html>`, `<head>`, `<body>`를 임의로 추가하지 않는다.

## 12. 실행 순서와 산출물

1. **기준 확인**: Git 상태·버전·동시 변경을 확인하고 실제 화면, 요청 경로, 설정 필드, 준비 조건과 테스트를 읽는다. 사용자/다른 작업자의 변경을 보존한다.
2. **누락 없는 화면 매핑**: 기존 기능마다 새 화면과 진입 경로를 대응시킨다. 새로 확인된 기능도 표에 포함하고, 이동·조건부 표시·고급 분리 이유를 기록한다.
3. **화면 골격 구현**: 로그인과 세 주 화면, 장치 목록/상세 탐색을 구현한다. 기존 서버 계약을 재사용하고 기능 로직 이동과 시각 변경을 구분한다.
4. **상태·저장 연결**: 장치 ID 기반 초안과 상태 모델, 저장 결과, 준비 조건, 요청 순서 보호를 연결한다. 원본/양식 동기화도 검증한다.
5. **표현 정리**: 한영 문구, 테마, 지원 범위, 조건부 조작, 개인정보 안내를 정리한다.
6. **자동 검증**: 아래 필수 시나리오의 UI/서버 테스트를 추가하거나 수정하고 실제 결과를 확인한다. 이전 DOM 구조만 고정하는 테스트는 새 사용자 흐름을 검증하도록 바꾼다.
7. **시각 검증**: 밝은/어두운 테마 × 한국어/영어 × 모바일/넓은 화면을 실제 렌더링해 확인한다. 읽기 어려움·넘침·초점 손실이 있으면 해당 부분을 수정한다.
8. **최종 보고**: 변경 화면, 보존 기능, 테스트 결과, 실제 캡처 경로, 미검증 범위와 남은 문제를 보고한다. 운영 적용 성공으로 표현하지 않는다.

필요한 경우 UI 자산을 같은 `homebridge-ui/` 범위의 작은 파일로 분리할 수 있다. 다만 현재 호스트의 자산 로딩·배포 포함 규칙을 확인하고 새 프레임워크를 기본 선택으로 삼지 않는다. UI 변경에 꼭 필요한 최소 응답 보강 외에는 런타임·명령·저장 스키마를 재설계하지 않는다.

## 14. 완료 판정

세 화면의 사용자 흐름이 동작하고, 기존 베타 기능이 빠짐없이 적절한 위치에 있으며, 상태·저장·명령의 실제 의미가 고객 문구와 일치해야 한다. 필수 자동 검증과 실제 화면 확인을 마치고 남은 문제를 명시해야 완료로 보고할 수 있다.

완료 보고에는 다음을 포함한다.

- 실행 기준 커밋·버전과 변경 파일.
- 기존 기능 → 새 화면의 대응표.
- 실제 실행한 검증 명령과 결과.
- 화면 캡처 또는 검토 가능한 미리보기 위치.
- 제공되지 않는 기능과 실기 확인이 필요한 범위.
- 게시·운영 변경을 하지 않았다는 사실.

### 이번 실행 결과

기준은 `3.0.0-beta.1`의 로컬 UI 재설계다. 기존 기능은 **내 장치**의 목록·상세·기기 조작·장치별 설정, **연결 설정**의 계정·집/방·Matter·자동 조명, **도움말**의 지원 범위·진단·전력 측정 설정으로 옮겼다.

브라우저 mock 검증은 70건, 서버 계약 검증은 25건, 전체 단위 테스트는 415건 통과했다. `tests/ui/appearance.spec.ts`가 생성한 로컬 캡처로 한영·밝은/어두운 테마·375/1200px의 8개 조합과 상세·연결·도움말·로그인 화면을 확인했다. 독립 semantic 검토도 서버 12건·UI 11건 통과했고 중요한 미해결 지적은 없다. UI는 인라인 HTML/CSS/JS 단편을 유지했고 npm 패키지는 119개 파일로 확인했다. 버전은 `3.0.0-beta.1` 그대로이며 `src/runtime/`, schema, package와 운영 환경은 바꾸지 않았다.

호스트의 `homebridge.request()`는 시간 초과 후 원 요청을 취소하는 API가 없다. 화면은 미응답 진단 요청을 최대 두 건으로 제한하고 닫힌 동안 새 요청을 멈추지만, 오래된 요청 자체가 즉시 취소되는 것은 아니다. 상태가 계속 확인되지 않으면 설정 화면을 닫았다 다시 열어 연결 상태를 재확인한다. 이 결과는 Homebridge 운영 iframe, 실제 Hejhome 기기·클라우드 명령, Apple Home/Matter 페어링, 게시·운영 적용을 검증한 것이 아니다. 확인되지 않은 카메라 영상·도어락 잠금·스마트 버튼 제스처 등의 기능은 새 화면에 사용 가능하다고 추가하지 않았다.
